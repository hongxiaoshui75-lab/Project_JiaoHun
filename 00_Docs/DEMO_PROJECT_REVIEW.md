## 本轮规则取舍

1. 总整理和本轮用户讨论优先于旧机制文档。最终失败为和尚获释、蔡瑞未被追究；普通失败为原有指控未被动摇。
2. 原总纲四轮保留在原文件；Demo采用两轮普通举证，索钱／去向／行李压缩成三段追加查问。
3. 普通两轮共用5点；最终三段会审独立刷新5点。失败按对应会审入口快照重试。
4. 不设开场“没有疑点”直接失败，不采用倒计时、自动解题和矛盾高亮。
5. 沈砚官职尚未定稿，代码与对白只称姓名，不添加刑房书吏或现代诉讼身份。
6. 帽子美术暂停，保留帽檐调查文字占位，不把先前未通过的内衬／帽胎方案定稿。
7. 围观者证言、帽子重新查验与现场比对是游戏新增。新写对白均为工作稿，不冒称原著逐字记载。
8. 剪刀数量、非人发、剪痕与材料相似各有证明边界；最终联系动机与经手经过，再持续查究并招供。

## 分工与集成

子任务分别负责剧情数据、纯逻辑引擎、存档模块、核心流程测试；另一次独立子任务负责界面按钮衔接测试。主任务统一模块契约、制作试玩界面、静态服务与打包工具，核对剧情和测试后集成。各子任务仅修改分配文件，未授权继续分派。

所有新增实现为零第三方依赖的 JavaScript 模块。浏览器游戏状态在本地运行，不需要账号和远端服务器。既可使用本机静态服务，也可使用同源码构建的独立 HTML 文件。
